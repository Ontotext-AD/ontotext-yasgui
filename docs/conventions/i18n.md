# Internationalization (i18n)

Rules for adding or changing translations.

## Where translations live

- All translations are in `ontotext-yasgui-web-component/src/i18n/locale-<lang>.json` (`en`, `fr`), loaded by
  `TranslationService`. YASGUI, YASQE and YASR are translated through the same service.
- Every key exists in **every** locale file. There is no validation script, so check both files yourself.
- The client can override or add translations through the component configuration; a key rename is a breaking
  change for clients that override it.

## Naming keys

- Group keys by area, then component: `yasgui.tab_list.close_tab.btn.label`,
  `yasqe.actions.save_query.button.tooltip`. Add a new key next to its area's existing keys.
- Name a key after its meaning (`close_last_tab.warning.message`), not after its English text.
- One message, one key: keep the sentence whole and pass the dynamic parts as parameters (`{{timeHuman}}`). Don't
  assemble it from fragment keys.
- One key per use: two actions that share wording still get separate keys.
- An element's `title` and `aria-label` describe the same thing: use the same key for both.
- Translate where the text is shown, at render time. Don't store translated strings in fields that then need a
  language-change subscription to stay current.

## Verifying

`cypress/e2e/languages.spec.cy.ts` covers language switching. Tests run in English.
